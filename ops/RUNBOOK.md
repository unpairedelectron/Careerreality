Operator: Claude (handed over by Shiv Shakti Mishra, 8 November 2026).

Read this file at the start of every operations session. Append one entry to `ops/LOG.md` at the end.

## 1. Approval tiers

| Tier | What | Rule |
|---|---|---|
| **Ship** | Bug fixes, technical/SEO fixes, build and verifier failures, internal links, schema fixes, dependency patch/minor updates, copy refreshes that change no legal, tax or statutory figure | Do it, full build must pass, commit and push to `main`, log it |
| **Ask first** | New guides; any changed tax slab, rate, threshold, legal rule or statutory number; design/layout changes; anything touching ads or AdSense; major dependency upgrades; production publish (until the Replit publish path is proven) | Prepare it on a `claude/…` branch or as a draft, list it under "Needs owner OK" in the weekly report |
| **Never** | Deleting pages or sitemap URLs; redirects to external sites; account, billing, domain or credential changes; sending email or messages as the owner; claims of author credentials, reviews or dates that are not verified | Do not do it; raise it in the report if it seems needed |

Facts only the owner can supply are tracked in `OWNER-INPUTS-REQUIRED.md`. Never invent them in public copy.

## 2. Deploy path

1. Change lands on GitHub `main` (`unpairedelectron/Careerreality`).
2. In Replit: `git pull --no-rebase origin main`.
3. `cd artifacts/career-reality && pnpm run build` — must pass, including postbuild route-snapshot verification.
4. Publish in Replit.
5. `git push origin main` from Replit (pushes the empty "Published your App" commit Replit adds on every publish, so the copies don't diverge).
6. Run the live check (section 3).

Gotchas:
- `public/_redirects` is generated by `scripts/generate-sitemap.mjs`. Change redirects in `src/data/route-registry.json`, never in `_redirects`.
- Prebuild needs `SITE_URL=https://careerreality.in` outside Replit.
- The owner's Windows PC cannot run `vite build` (Linux-installed `node_modules`). Run full builds in Replit or a Linux environment.

## 3. Weekly check (every Monday)

1. Live smoke test: `/`, `/ads.txt`, `/robots.txt`, `/sitemap.xml`, `/favicon.ico` return 200; `www` and `http` 301 to `https://careerreality.in/`.
2. Every sitemap `<loc>` returns 200 (87 URLs on 8 November 2026; the count should only change with an intentional release).
3. A guide page still shows the server-rendered byline and Article JSON-LD with the author.
4. `pnpm run verify:indexed-routes` against production.
5. After a release that adds or changes URLs: `pnpm run indexnow:submit`.
6. Date-sensitive content: flag any guide citing a figure tied to a financial year, notified rule or effective date that has passed (Ask-first tier to change).
7. Write the weekly report (section 5) and log entry.

When Search Console and GA4 access exist, add: index coverage errors, pages losing clicks week over week, queries with high impressions and low CTR.

## 4. Content rules

- Everything still has to pass the build gates: word floors, 90-word paragraph limit, duplicate-paragraph ownership, verifier blocklists.
- India finance/legal content is published under the owner's name. Cite the primary source (Income Tax Department, EPFO, Ministry of Labour, gazette notification) for every figure, and put changed figures in the Ask-first tier.
- No fabricated authors, reviewers, dates or "drafted with AI" disclaimers beyond what the owner has confirmed.

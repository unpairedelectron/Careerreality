---
name: Career decision engine
description: Durable rules for turning changing profile and market inputs into grounded career actions.
---

The career brief is a decision synthesis, not a static market card. Its headline, diagnosis, and next move must change when the user's situation, target direction, compensation, location, company signal, or evidence changes. In resume matching, a keyword in wording such as “experience is not documented” is not positive evidence, and a confirmed gap requires an explicit candidate denial; match multi-word skill names without losing the denial phrase. When a skill matcher captures its surrounding delimiter, calculate quote and attribution boundaries from the actual skill position so an opening quote is not skipped. When splitting resume evidence into statements, handle punctuation before a closing quote so the next statement does not inherit the quote's source context.

In job-posting requirement extraction, treat tools named only in company-context sentences (for example, “our internal prototype uses Python”) as context, not candidate requirements, unless the sentence also carries a clear requirement or responsibility signal. Preserve explicit skills requirements and responsibility statements.

For the Job Posting Reality Check, keep the score scoped to evidence present in supplied resume wording, not capability or hiring odds. Mandatory requirements count twice preferred items; direct, transferable, partial, and undocumented evidence map to 100%, 75%, 50%, and 0%. Missing evidence is not a confirmed skill gap; only a user-confirmed mandatory gap can override the score recommendation. The current 40/70 recommendation bands are judgment-based and not empirically validated.

**Why:** A generic promotion-style action can be actively wrong for someone switching domains, recently laid off, already above market, or facing a company watch signal. Keyword-only matching can also turn omission into evidence or miss explicit denials when a skill name has multiple words. Quote delimiters included in a token match can cause copied denials to be mislabeled as candidate-authored unless attribution uses the skill's true position. Sentence boundaries around quoted excerpts can otherwise merge copied text with a separate candidate statement. Company-stack mentions can otherwise inflate the extracted requirements with irrelevant tools.

**How to apply:** Match market evidence by role, target direction, city, and experience before comparing compensation. Classify situation with negation-aware rules such as “not looking.” For resume skills, test positive evidence, explicit denial, and omission wording separately, including multi-word skill names and quoted statements adjacent to direct statements; base quote checks on the matched term's actual span. In requirement extraction, pair company-context examples with explicit mandatory/preferred/responsibility controls. Treat resume extraction as supporting evidence, not proof of impact or sponsorship. Keep team-level unknowns visible, and test every new branch with a contrasting profile case. Live job-demand data may corroborate a read, but provider failure must be explicit and never fall back to stale demand. When presenting the posting score, keep its wording-evidence scope and unvalidated thresholds visible; revise the score or recommendation only with evidence and regression tests.
